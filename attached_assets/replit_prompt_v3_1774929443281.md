# IrrigBucket — Centre Pivot UX Overhaul (Replit Prompt)

## Goal

Redesign the Centre Pivot flow so that a user who has **never done a bucket test before** can get a professional-quality test setup by just entering their pivot specs. The app should auto-calculate everything (offset, sections, bucket counts, spacing) but let experienced users adjust the numbers if they want more precision.

---

## Current Problem

The app currently asks the user to manually enter: start offset distance, number of buckets, and bucket spacing. Most farmers don't know what values to use. The app should calculate these automatically from basic pivot specs (length + number of spans), then present an editable setup.

### SCREEN 2 — Test Plan (Auto-Calculated, Editable)

After the user clicks "Calculate Bucket Test Setup", the app should auto-calculate the complete test setup and present it as an **editable table** on the plan screen.

#### Auto-Calculation Logic

```javascript
// Inputs
const pivotLength = inputs.pivotLength;       // e.g. 840
const numSpans = inputs.spanCount;            // e.g. 8
const cornerArm = inputs.cornerArmLength || 0; // e.g. 85
const hasGun = inputs.hasEndGun === 'Yes';
const gunWettedWidth = inputs.gunWettedWidth || 0;

// Calculate span length
const spanLength = pivotLength / numSpans;

// Skip first 2 spans (inner spans too unreliable)
const skipSpans = 2;
const startOffset = Math.round(skipSpans * spanLength);

// Testable pivot length (from offset to tip, excluding corner arm)
const testablePivotLength = pivotLength - startOffset;

// Split testable length: inner half gets wider spacing, outer half gets tighter spacing 
// The split point is the midpoint of the testable area
const innerLength = Math.round(testablePivotLength / 2);
const outerLength = testablePivotLength - innerLength;

// Target bucket counts: aim for ~23 per section (professional standard)
// Use span length as a guide for spacing:
// Inner spacing ≈ span length / 5, rounded to a clean number
// Outer spacing ≈ span length / 10, roughly half the inner spacing
// This naturally gives more data points on the outer spans (which irrigate more area)
const innerSpacing = Math.round(innerLength / 22);  // ~23 buckets
const outerSpacing = Math.max(5, Math.round(outerLength / 22));  // ~23 buckets, min 5m

const innerBuckets = Math.floor(innerLength / innerSpacing) + 1;
const outerBuckets = Math.floor(outerLength / outerSpacing) + 1;

// Gun section (only if has end gun)
let gunBuckets = 0;
let gunSpacing = 0;
if (hasGun && gunWettedWidth > 0) {
  gunBuckets = 8;  // Professional standard: 4 left + 4 right
  gunSpacing = Math.round(gunWettedWidth / (gunBuckets - 1));
}

const totalBuckets = innerBuckets + outerBuckets + gunBuckets;
```

Display the auto-calculated setup in a clean, editable table card. This replaces the current static arrangement text. It should look like this:

**Card Title:** "Your Recommended Test Setup"

**Subtitle/Explanation paragraph:**

**Table with editable cells:**

| Section | From | To | Buckets | Spacing | |
|---------|------|-----|---------|---------|---|
| Inner Spans | 210 m | 525 m | `[editable: 23]` | `[editable: 14] m` | |
| Outer Spans | 525 m | 840 m | `[editable: 23]` | `[editable: 14] m` | |

- The "Buckets" and "Spacing" columns should be **editable number inputs** (not plain text), styled inline within the table cells.
- When the user changes the bucket count for a section, automatically recalculate that section's spacing (spacing = section length / (buckets - 1)), and vice versa.
- The "From" and "To" columns are display-only (calculated from offset + cumulative lengths).
- Show the Total row that sums all bucket counts.
- Below the table, add a small note: `"Tip: More buckets = more precise results. Fewer buckets = quicker test. 40–50 total is the professional standard for nozzle-level accuracy."`

#### Gun Section Guidance

If the user selected "Has End Gun = Yes", add a guidance card below the setup table:

> **🔫 End Gun Test**
> Your pivot's end gun will be tested with [8] buckets placed across its [60 m] throw width. Place these buckets in a line **perpendicular to the pivot arm** at the gun's position, spanning from outside (away from pivot) to inside (toward pivot). Label the outside buckets as "Left" and inside buckets as "Right" for the section analysis.

If "Has End Gun = No", don't show this card or the gun row in the table.

#### Placement Guidance (keep the checklist but update arrangement text)

Update the main arrangement instruction text to be section-aware:

> "Place buckets in a straight RADIAL line starting [startOffset] m from the pivot centre, spaced as shown in the setup table above. The first [innerBuckets] buckets (Inner Spans) are spaced [innerSpacing] m apart. The next [outerBuckets] buckets (Outer Spans) are spaced [outerSpacing] m apart.
> [If gun:] Place an additional [gunBuckets] buckets perpendicular to the pivot arm at the gun position, spaced [gunSpacing] m apart across the [gunWettedWidth] m throw width.
> Position all radial buckets AT LEAST 15 m from any wheel tracks."

### SCREEN 3 — Data Entry

The data entry screen should work as before, but with these improvements:

1. **Pre-populated section definitions**: The section definitions (Inner Span, Outer Span, End Gun) should be **auto-filled** based on the setup table. The user should NOT need to manually type section names or bucket ranges. Calculate them from the bucket counts:
   - Inner Span: bucket 1 to [innerBuckets]
   - Outer Span: bucket [innerBuckets + 1] to [innerBuckets + outerBuckets]
   - End Gun: bucket [innerBuckets + outerBuckets + 1] to [totalBuckets]

2. **Section headers in the volume grid**: Add visual section dividers within the bucket volume grid. Before bucket #1, show a small header "Inner Spans (buckets 1–23)". Before the first outer span bucket, show "Outer Spans (buckets 24–46)". Before the gun buckets, show "End Gun (buckets 47–54)". This helps users know which physical area each bucket corresponds to.

3. **Enter key navigation** (if not already implemented): When the user presses Enter on a bucket input, focus moves to the next bucket input. Set `enterkeyhint="next"` on each input (except the last which uses `enterkeyhint="done"`). Add a keydown listener:
```javascript
input.addEventListener('keydown', (e) => {
  if (e.key === 'Enter') {
    e.preventDefault();
    const nextInput = volumeInputs[index + 1];
    if (nextInput) { nextInput.focus(); nextInput.select(); }
    else { input.blur(); }
  }
});
```

## Implementation Notes

### Store section info in `currentSetup`

The `getSetup()` function should return a `sections` array in the setup object so the data entry screen can auto-populate:

```javascript
return {
  numBuckets: totalBuckets,
  spacing: outerSpacing, // primary spacing shown in the header
  lineLength: pivotLength,
  startOffset,
  sections: [
    { name: 'Inner Spans', buckets: innerBuckets, spacing: innerSpacing, from: startOffset, to: startOffset + innerLength },
    { name: 'Outer Spans', buckets: outerBuckets, spacing: outerSpacing, from: startOffset + innerLength, to: pivotLength },
    ...(hasGun ? [{ name: 'End Gun', buckets: gunBuckets, spacing: gunSpacing, from: 0, to: gunWettedWidth, isGun: true }] : []),
  ],
  arrangement: `...`, // updated text as described above
  testDuration: `...`,
  diagCaption: `...`,
};
```

### Conditional field visibility

The "Gun Wetted Width" field should only be visible when "Has End Gun" is "Yes". Handle this by adding an event listener to the "Has End Gun" select dropdown that shows/hides the gun width field. When rendering the form fields in `selectType()`, check if a field has a `showWhen` condition and apply it.

Add `showWhen` property to the gun wetted width field definition:
```javascript
{ id: 'gunWettedWidth', label: 'Gun Wetted Width', unit: 'm', type: 'number', placeholder: 'e.g. 60', min: 5, max: 200, showWhen: { field: 'hasEndGun', value: 'Yes' } }
```

And the "Has End Gun" field should be a select:
```javascript
{ id: 'hasEndGun', label: 'Has End Gun?', unit: '', type: 'select', options: ['No', 'Yes'], value: 'No' }
```

Update the form rendering code in `selectType()` to handle `type: 'select'` and `showWhen` conditions.

### Editable setup table interaction

When the user edits a bucket count in the setup table, recalculate that section's spacing:
```javascript
newSpacing = sectionLength / (newBucketCount - 1);
```

When the user edits a spacing value, recalculate that section's bucket count:
```javascript
newBucketCount = Math.floor(sectionLength / newSpacing) + 1;
```

Update the total row whenever any value changes. Store the edited values so they carry through to the data entry screen.

## Important: Do NOT Change

- **DU formula**: Must remain `DU = 1 - (STDEV.P / MEAN)` — the CV method
- **Application depth formula**: Must remain `depth = (1000 × volume_mL) / (π × radius_mm²)`
- **Section breakdown table on results screen**: Keep as-is
- **The other irrigator types** (K-Line, Travelling Gun, Rotary Boom, Fixed Grid, Linear Move): Don't modify their flows
