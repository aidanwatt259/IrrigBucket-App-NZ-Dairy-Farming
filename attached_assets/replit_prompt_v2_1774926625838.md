# IrrigBucket — Update Prompt for Replit

## Context

This app is an irrigation bucket test calculator built for NZ dairy farmers. An industry professional tested it with real-world data from a centre pivot (840m radius, ~49 buckets) and a travelling gun (8 buckets). His results almost matched the app, but he identified several issues that need fixing to make the app usable for professionals.

---

## Changes Required (4 areas)

---

### 1. CENTRE PIVOT: Let users control bucket count, spacing, and start offset

**Problem:** The centre pivot `getSetup()` function auto-calculates bucket count with a formula that caps it too low. The professional used 49 buckets across 3 sections with different spacings:
- Inner span: 23 buckets at 21m spacing
- Outer span: 23 buckets at 11m spacing  
- End gun: 3 buckets at 5m spacing

He also started measuring at 185m from the centre (not from 0m), because the inner spans near the pivot centre are too unreliable to measure accurately.

**Fix:** Add three new fields to the Centre Pivot system details form:

1. **"Start Offset (skip inner area)"** — a number field (unit: `m`, default: `0`, placeholder: `e.g. 185`). This tells the user where to START placing buckets, measured from the pivot centre. Add a hint below: `"Inner spans near the pivot centre rotate slowly and are unreliable to test. Start from where reliable measurement begins."`

2. **"Number of Buckets"** — a number field (min: 4, max: 200, no default — let the user choose). Remove the automatic bucket count calculation. The user should decide how many buckets to use based on their needs. Add a hint: `"More buckets = more precise results. Professionals typically use 40–50+ buckets."`

3. **"Bucket Spacing"** — a number field (unit: `m`, placeholder: `e.g. 11`). Let users set their own spacing. Add a hint: `"Outer spans typically use tighter spacing (e.g. 11m) than inner spans (e.g. 21m) for better resolution."`

**Update the `getSetup()` function for `centrePivot`** to use these user-supplied values instead of auto-calculating:
```javascript
getSetup: (inputs) => {
  const pl = inputs.pivotLength;
  const startOffset = inputs.startOffset || 0;
  const numBuckets = inputs.numBuckets || Math.max(12, Math.ceil((pl - startOffset) / (inputs.bucketSpacing || 15)));
  const testableLength = pl - startOffset;
  const actualSpacing = inputs.bucketSpacing || +(testableLength / (numBuckets - 1)).toFixed(1);
  return {
    numBuckets,
    spacing: actualSpacing,
    lineLength: pl,
    startOffset,
    arrangement: `Place ${numBuckets} buckets in a straight RADIAL line starting ${startOffset > 0 ? startOffset + 'm from the pivot centre' : 'near the pivot centre'} out to the last tower/tip. Space them ${actualSpacing}m apart. Position the line AT LEAST 15m from any wheel tracks.`,
    testDuration: `Wait for the full revolution (approx. ${inputs.revolutionTime} hours) so the pivot passes completely over all buckets.`,
    diagCaption: `Radial line ${startOffset > 0 ? 'from ' + startOffset + 'm' : 'from centre'} to tip — ${numBuckets} buckets at ${actualSpacing}m spacing`,
  };
},
```

Add the three new fields to the `centrePivot.fields` array:
```javascript
{ id: 'startOffset', label: 'Start Offset (skip inner area)', unit: 'm', type: 'number', placeholder: 'e.g. 185', min: 0, max: 500, value: 0 },
{ id: 'numBuckets', label: 'Number of Buckets', unit: '', type: 'number', placeholder: 'e.g. 46', min: 4, max: 200, required: true },
{ id: 'bucketSpacing', label: 'Bucket Spacing', unit: 'm', type: 'number', placeholder: 'e.g. 11', min: 1, max: 50, required: true },
```

**Also add an info/guidance note** on the bucket test plan screen when the irrigator type is centre pivot. Before the existing pre-test checklist, add a guidance card that says:

> **Where to start placing buckets:**  
> The inner spans closest to the pivot centre rotate very slowly, making bucket test measurements unreliable in this area. It is recommended to start placing buckets from the point where reliable irrigation measurement begins — typically after the first few spans (e.g. 150–200m from centre for large pivots). Your start offset is set to [startOffset]m.
>
> **Why more buckets matter:**  
> More buckets give you more precise data about each nozzle's performance. If you're checking irrigator efficiency, 12–20 buckets gives a general estimate. If you're checking individual nozzle accuracy, use 40–50+ buckets with tighter spacing on the outer spans.

### 2. ENTER KEY NAVIGATION between bucket volume inputs

**Problem:** When entering bucket volumes on a phone or field device, users have to tap each input individually. The professional says pressing Enter should automatically move focus to the next bucket input.

**Fix:** Add an event listener to each bucket volume input so that when the user presses Enter (or the "Next"/"Go" button on mobile keyboards), the focus moves to the next bucket input. Add this inside the `showDataEntry()` function, right after creating the volume grid inputs:

```javascript
// Add Enter key navigation between bucket inputs
const volumeInputs = grid.querySelectorAll('input[type="number"]');
volumeInputs.forEach((input, index) => {
  input.addEventListener('keydown', (e) => {
    if (e.key === 'Enter') {
      e.preventDefault();
      const nextInput = volumeInputs[index + 1];
      if (nextInput) {
        nextInput.focus();
        nextInput.select();
      } else {
        // Last bucket — blur to dismiss keyboard
        input.blur();
      }
    }
  });
});
```

Also set `enterkeyhint="next"` on each bucket input (except the last one which should be `enterkeyhint="done"`), so mobile keyboards show a "Next" button instead of "Go":

```javascript
cell.innerHTML = `
  <label>#${i + 1}</label>
  <input type="number" id="vol-${i}" placeholder="mL" min="0" max="10000" inputmode="decimal"
         enterkeyhint="${i < currentSetup.numBuckets - 1 ? 'next' : 'done'}">
`;
```

**Problem:** Same issue as pivots — the gun bucket count is auto-calculated to a low number. The professional tested a gun with 8 buckets split into two sides (4 left/outside, 4 right/inside).

**Fix:** Add a **"Number of Buckets"** field to the `travellingGun` fields array as well:
```javascript

```

Update the `travellingGun.getSetup()` to use user-specified count when provided:

```javascript
const numBuckets = inputs.numBuckets || Math.max(12, roundToMultipleOf4(Math.ceil(tw / spacing)));
```

## Important: Do NOT change the DU formula

The DU calculation uses `DU = 1 - (STDEV.P / MEAN)` — this is the correct NZ industry standard (CV method). Do NOT change this formula or revert it to lower-quarter DU.
